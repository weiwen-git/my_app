## 1. 项目概述

### 1.1 背景

weiwen 同时运营多个店铺（ICBU 主店、1688 店、独立站等），每日/每周/每月有大量重复性工作，靠记忆和记事本管理，容易出现：该做的事忘做、临时任务散落各处、每周数据无处归档、零散信息没有统一存放处。

现有工具（Excel、备忘录、浏览器收藏夹）各自为政，且都不适配"按店铺 + 按周期"的工作方式。

### 1.2 产品目标

做一个**部署在自有服务器上的单用户 Web 工作台**，把「固定重复的工作」「临时接到的事」「要记录的数据」「零散信息」四类内容收拢到一个入口。

### 1.3 成功标准

上线两周后，同时满足以下三条才算成功：

| 编号 | 标准 |
|---|---|
| SC-1 | 每个工作日都主动打开过（不靠提醒） |
| SC-2 | 工作清单的勾选率 > 70% |
| SC-3 | 第二周打开频次不低于第一周（不是新鲜感驱动） |

### 1.4 明确不做

| 不做 | 原因 |
|---|---|
| 多用户 / 权限 / 注册 | 只有一个人用 |
| 移动端适配 | 只在电脑上用 |
| 平台接口自动同步 | 数据量小，手动填更可控 |
| 图表 / 大屏 | 需求是记数，不是看趋势 |
| 消息推送 | 会主动打开，不需要打扰 |
| 富文本编辑器 | 笔记用纯文本足够，引重型编辑器不值 |
| 自定义主题 / 动画 | 实用优先 |
| 翻译实际调用（本期） | 第三批才做，本期只做界面 |

## 2. 用户与使用场景

### 2.1 用户画像

| 项 | 内容 |
|---|---|
| 身份 | 跨境电商卖家 / 外贸运营负责人 |
| 主营 | 定制金属礼品（挑战币、宠物标签、徽章） |
| 平台 | 阿里巴巴国际站（多店铺）、1688 |
| 设备 | Windows 笔记本（14 寸，有效宽度约 1440px） |
| 技术水平 | 有开发经验，能自己部署和排查 |
| 使用时段 | 早上开工前、晚上收工前为主 |

### 2.2 核心场景

| 编号 | 场景 | 频率 |
|---|---|---|
| S-1 | 早上打开，看今天各店要做哪些事，边做边勾 | 每天 |
| S-2 | 中间接到临时的事，随手记进待办，做完勾掉 | 不定期 |
| S-3 | 每周一把上周数据填进对应店铺的数据表 | 每周 |
| S-4 | 想到什么随手记一张便签，之后整理成笔记 | 不定期 |
| S-5 | 新建一个店铺后，把它的日常工作和数据表配起来 | 低频 |

### 2.3 关键用户旅程

**旅程 A：早上开工**
```
登录 → 落在工作清单（默认「全部店铺」）
  → 看到逾期 2 项（橙色区），先处理掉
  → 扫一眼各店待办，逐条勾选
  → 中途接到电话，切到待办，加一条临时任务
```

**旅程 B：周一录数据**
```
点「数据」→ 总览看到 3 张表
  → 进「ICBU 周数据」
  → 从 ICBU 后台复制一周数据 → 粘贴 CSV → 确认导入
  → 底部合计自动更新，转化率显示的是平均值
```

**旅程 C：新增一个店铺**
```
工作清单页 → 点店铺 Tab 末尾齿轮 → 弹窗新增店铺
  → 点「管理模板」→ 为该店建每日/每周/每月模板
  → 保存，当天清单立即出现
```

## 3. 产品结构

### 3.1 信息架构

```
个人工作台
├── 工作清单（首页）          固定重复工作，按店铺 + 按周期
├── 数据                     自定义列的数据表集合
│   ├── 数据总览              所有数据表一览
│   └── 数据表详情            某张表的记录
├── 待办                     临时接到的、不属于店铺的事
├── 便签                     短内容卡片墙
├── 笔记                     标题 + 长正文
└── 翻译                     中英互译（本期占位）
```

### 3.2 概念定义（核心）

| 概念 | 定义 | 归属店铺 | 有周期 | 能否手动新增 |
|---|---|---|---|---|
| **工作清单** | 固定、重复、与店铺绑定的工作 | ✅ | ✅ | ❌ 只能由模板生成 |
| **待办** | 临时接到的、不属于任何店铺的事 | ❌ | ❌ | ✅ |
| **数据** | 自定义列的数据表 | ❌ | 由列语义决定 | ✅ |
| **便签** | 短内容，一眼看完 | ❌ | ❌ | ✅ |
| **笔记** | 标题 + 长正文 | ❌ | ❌ | ✅ |

**判别规则**（用户心智模型）：
> 这件事会反复做，且属于某个店 → 建模板，进工作清单。
> 这件事只做一次，或者是临时冒出来的 → 进待办。

## 4. 功能需求

### 4.1 F-01 登录

**目的**：阻止公网上的任何人访问数据。

| 项 | 说明 |
|---|---|
| 入口 | 任意未登录访问 |
| 页面 | 居中卡片：用户名、密码、登录按钮 |
| 账号来源 | 环境变量 `WB_USERNAME` |
| 密码来源 | 环境变量 `WB_PASSWORD_HASH`（bcrypt） |

**交互**
1. 用户名 + 密码 → 提交 → 成功签发 HttpOnly Cookie → 跳工作清单
2. 回车可提交；提交中按钮 loading
3. 失败统一提示「用户名或密码错误」（不区分是哪个错）
4. 连续失败 5 次锁定 10 分钟，提示剩余时间
5. 登录后顶栏显示「退出」，点击清 Cookie 回登录页

**边界**
- 无注册、无找回密码、无"记住我"
- 页面文案不暴露"单用户"事实

**验收**
- [ ] AC-01-1 未登录访问任意页面被跳登录
- [ ] AC-01-2 未登录直接调任意 `/api/*` 返回 401
- [ ] AC-01-3 错 5 次后锁定，提示剩余分钟数
- [ ] AC-01-4 退出后回退按钮无法回到工作清单

### 4.2 F-02 工作清单（首页）

**目的**：一眼看到今天各店要做什么。

**入口**：登录后自动进入；侧边栏第一项。

**页面结构**

| 区域 | 内容 |
|---|---|
| 页头 | 标题「工作清单」+ 今天日期（含星期）+「管理模板」按钮 |
| 店铺 Tab | 全部 / 各启用店铺 / 齿轮（管理店铺） |
| 周期 Tab | 每日 / 每周 / 每月，各带未完成数量角标 |
| 逾期区 | 橙色区块，常驻展开（仅在有逾期时出现） |
| 列表 | 待办条目，含 checkbox、标题、标记、删除 |
| 底部 | 今日完成进度「x / y」+ 提示「清单由模板自动生成」 |

**核心规则**

| 规则 | 说明 |
|---|---|
| 生成时机 | 每次进入页面触发一次，接口幂等 |
| 不提供新增 | 页面上没有"新增工作"入口，只能通过模板 |
| 全部店铺视图 | 按店铺分组显示，每组有小标题（店名 + 未完成数） |
| 单店视图 | 平铺，不分组，不显示店铺标签 |
| 角标含义 | 选「全部」= 各店合计；选单店 = 该店数量 |
| 门店标签 | 停用店铺的历史条目仍显示，标签置灰 |

**交互**

| 操作 | 行为 |
|---|---|
| 勾选 | 立即置灰划线，落库 `status=done` + `done_at`；可取消勾选 |
| 删除 | 二次确认，删除后刷新不复活 |
| 切换店铺/周期 | 只重新拉取列表，不整页刷新 |
| 点「管理模板」 | 跳模板管理页，并自动带入当前店铺筛选 |
| 点齿轮 | 打开店铺管理弹窗 |

**空态（首次使用）**
```
还没有店铺和工作清单

① 添加你的店铺
② 为每个店建工作清单模板
③ 明天开始自动出现在这里
[ 添加店铺 ]  [ 建模板 ]
```
店铺入口在空态中**显式呈现**，不依赖齿轮。

**验收**
- [ ] AC-02-1 打开页面自动生成当天清单，重复打开不重复
- [ ] AC-02-2 页面找不到任何"手动新增"入口
- [ ] AC-02-3 「全部」视图按店铺分组，单店视图平铺
- [ ] AC-02-4 逾期区有内容时自动展开
- [ ] AC-02-5 空态三步引导可见，按钮可点

### 4.3 F-03 模板管理

**目的**：定义"哪些事会每天/每周/每月重复出现"。

**入口**：工作清单页「管理模板」按钮（不占侧边栏）。

**列表字段**

| 字段 | 说明 |
|---|---|
| 标题 | 工作内容 |
| 店铺 | 所属店铺名 |
| 周期 | 每日 / 每周三 / 每月 5 号（中文展示） |
| 排序 | 数字，可上下移 |
| 状态 | 启用 / 停用 |
| 操作 | 编辑 / 停用 / 删除 |

**新增/编辑表单**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 标题 | 文本 | ✅ | 如「查看昨日询盘」 |
| 店铺 | 下拉 | ✅ | 来自店铺表 |
| 周期类型 | 下拉 | ✅ | 每日 / 每周 / 每月 |
| 周几 | 多选 | 条件 | 选「每周」时出现，周一到周日 |
| 几号 | 数字 | 条件 | 选「每月」时出现，1–31 |
| 排序 | 数字 | ❌ | 默认 0 |

**关键规则**

| 规则 | 说明 |
|---|---|
| 保存后补生成 | **保存模板后立即检查是否匹配今天，匹配则当场生成今日条目**，提示「已加入今日清单」 |
| 每月兜底 | 选「每月 31 号」时，当月无 31 号（如 2 月）则在当月最后一天生成 |
| 停用 | 停用后不再生成新条目，历史条目保留 |
| 删除 | 软删除，历史条目保留 |

**验收**
- [ ] AC-03-1 选「每周」出现周几选择，选「每月」出现几号
- [ ] AC-03-2 新建「每日」模板后，当天清单立即出现该条目
- [ ] AC-03-3 建「每月 31 号」，在 2 月能于最后一天生成
- [ ] AC-03-4 停用后次日不再生成

### 4.4 F-04 店铺管理

**目的**：维护店铺列表，作为工作清单和数据的归属维度。

**入口**：工作清单页店铺 Tab 末尾的齿轮图标（弹窗）。

| 字段 | 说明 |
|---|---|
| 店铺名 | 必填，唯一 |
| 短名 | 选填，Tab 上显示；空则用全名 |
| 排序 | 数字 |
| 状态 | 启用 / 停用 |

**关键规则**

- 停用后：不再生成新条目，历史条目仍显示（店铺标签置灰），数据表中该店记录保留

**验收**
- [ ] AC-04-1 新增店铺后，Tab 立即出现
- [ ] AC-04-2 找不到"删除店铺"入口，只有停用
- [ ] AC-04-3 重名店铺保存时被拒绝

### 4.5 F-05 待办

**目的**：收纳临时接到的、不属于任何店铺的事。

**入口**：侧边栏「待办」。

**页面结构**

| 区域 | 内容 |
|---|---|
| 页头 | 标题 + 未完成数 + 「+ 新增待办」 |
| 列表 | checkbox、标题、优先级标签、截止状态、完成、删除 |
| 已完成区 | 折叠，显示「已完成 N 项」，可展开 |

**字段**

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| 标题 | 文本 | ✅ | |
| 备注 | 多行文本 | ❌ | |
| 优先级 | 枚举 | ❌ | 高（红）/ 普通（蓝，默认）/ 低（灰） |
| 截止日 | 日期 | ❌ | 可空 |

**展示规则**

| 情况 | 显示 |
|---|---|
| 截止日 = 今天 | 「今天截止」橙色 |
| 截止日 = 明天 | 「明天截止」橙色 |
| 截止日 > 明天 | 「10-20 截止」灰色 |
| 截止日已过且未完成 | 日期标红 |
| 无截止日 | 「无截止」浅灰 |

**边界**
- 无店铺字段、无周期字段
- 完成后进已完成区，不删除
- 删除为硬删除

**验收**
- [ ] AC-05-1 待办页面没有任何店铺或周期相关字段
- [ ] AC-05-2 截止日已过的未完成项日期标红
- [ ] AC-05-3 完成后折叠进已完成区，可展开查看

### 4.6 F-06 数据

**目的**：存放自定义列的数据表，比如各店的周数据、广告消耗。

**结构**：数据总览 → 数据表详情（两层）

#### F-06-1 数据总览

| 列 | 内容 |
|---|---|
| 表名 | 点击进入记录页 |
| 列数 | 该表有多少列 |
| 记录数 | 该表有多少行 |
| 最近更新 | 最后一条记录的时间 |
| 操作 | 进入 / 改名 / 删除 |

**目的**：让用户知道有哪些表；同时解决"删除当前表后无处可去"的问题。

#### F-06-2 数据表详情

**页面结构**

| 区域 | 内容 |
|---|---|
| 页头 | 表名 + 记录数 +「管理列」「粘贴 CSV」「+ 新增记录」 |
| 表格 | 按列定义动态渲染 |
| 底部 | 合计行 + 合计规则说明 |

**列类型**

| 类型 | 对齐 | 输入控件 | 合计 |
|---|---|---|---|
| 数字 number | 右 | 数字输入框 | 可选 sum / avg / none |
| 文本 text | 左 | 文本框 | 不计 |
| 日期 date | 左 | 日期选择器 | 不计 |

**列管理（弹窗）**

| 操作 | 说明 |
|---|---|
| 新增列 | 名称 + 类型 + 合计方式 |
| 改名 | 同表内**列名唯一** |
| 改类型 | 改为数字时需校验已有值全部可转数字，否则拒绝 |
| 改合计方式 | sum / avg / none |
| 调整顺序 | 上移 / 下移 |
| 删除列 | 二次确认，明确提示「该列数据将一并删除」 |

**行操作**

| 操作 | 说明 |
|---|---|
| 新增记录 | 按列定义生成输入控件 |
| 编辑 | 弹窗修改，保存后刷新 |
| 删除 | 二次确认 |
| 粘贴 CSV | 按当前列顺序解析，支持带/不带表头 |

**排序**：按创建时间倒序（最新在上）。

**合计行示例**

```
合计 / 均值   115    24,646    880    3.5%    —
              求和    求和     求和   平均     不计
```

底部必须有说明文字，告诉用户每列用的是哪种合计规则。

**验收**
- [ ] AC-06-1 新增列后表格立即多一列，无需重启
- [ ] AC-06-2 转化率列设为"平均"后，合计行显示平均值而非求和
- [ ] AC-06-3 同表内建两个同名列被拒绝
- [ ] AC-06-4 粘贴 CSV 字段数不符时整体拒绝并指出行号
- [ ] AC-06-5 删除当前查看的表后跳转到总览，不白屏

## 5. 业务规则汇总

### 5.1 周期生成

| 周期 | 存储值 | 生成时机 |
|---|---|---|
| 每日 | `daily` | 每天（含周六日） |
| 每周 | `weekly:1` ~ `weekly:7` | 指定周几 |
| 每月 | `monthly:1` ~ `monthly:31` | 指定几号；**当月无该日取最后一天** |

### 5.2 未完成顺延

| 规则 | 说明 |
|---|---|
| 触发 | 未完成的条目在次日带入 |
| 实现 | **更新 `task_date` + `carried+1`**，不新建记录 |
| 原始日期 | `origin_date` 不变，用于历史统计 |
| 标记 | 前端显示「昨日未完成」或「未完成顺延 N 天」 |
| 上限 | 顺延满 7 天停止带入，移入逾期区 |
| 逾期区 | **常驻展开**（有内容时），提供「完成 / 放弃」 |
| 历史 | 按 `origin_date` 统计：「该日原有 X 项，其中 Y 项已顺延」 |

### 5.3 其他

| 规则 | 定义 |
|---|---|
| 时区 | 全局固定 `Asia/Shanghai`，所有"今天"以北京时间为准 |
| 门店删除 | 只能停用，不真删 |
| 数据合计 | 按每列 `agg`：sum / avg / none |
| 列名 | 同表内唯一 |
| CSV | 按当前列顺序解析，字段数不符整体拒绝并报行号 |
| 删除确认 | 模板、店铺、数据表、笔记、待办删除均需二次确认 |

## 6. 数据模型

### 6.1 实体关系

```
shops ──1:N──> task_templates ──1:N──> task_instances
shops ──1:N──> task_instances

data_sheets ──1:N──> data_columns
data_sheets ──1:N──> data_rows

todos            （独立）
sticky_notes     （独立）
notes            （独立）
```

### 6.2 表结构

共 9 张表，详细字段见 `site-setup.md` §6：

| 表 | 用途 | 关键约束 |
|---|---|---|
| `shops` | 店铺 | 无 |
| `task_templates` | 工作清单模板 | `shop_id`, `repeat_rule` |
| `task_instances` | 工作清单条目 | `task_date`（当前）+ `origin_date`（原始） |
| `todos` | 临时待办 | 无店铺字段 |
| `sticky_notes` | 便签 | 无 |
| `notes` | 笔记 | 无 |
| `data_sheets` | 数据表 | 无 |
| `data_columns` | 列定义 | `type` + `agg` |
| `data_rows` | 数据行 | 值存 `values_json` |

**设计取舍说明**：数据行用 JSON 存值，因为列完全自定义。代价是聚合查询要解析 JSON，收益是**加列永不改表结构**。

## 9. 技术架构

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | Vue 3 + vue-router + Element Plus + Vite | 不引 Pinia / axios / tailwind |
| 后端 | FastAPI + Uvicorn | 纯 API，同时托管前端静态文件 |
| 数据库 | SQLite 单文件 | `data/workbench.db` |
| 鉴权 | 用户名 + bcrypt + HttpOnly Cookie Session | Session 存内存 |
| 部署 | Docker 多阶段构建 + Nginx | 单容器 |
| 备份 | cron 每日复制 | 保留 14 份 |

**说明**：前端用 `fetch` 封装（约 20 行），不引 axios；登录态用模块级 `ref`，不引 Pinia。

## 10. 部署与运维

| 项 | 要求 |
|---|---|

## 13. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 范围持续扩大 | 一直做不完，上不了线 | 第一批砍到 6 个模块，先上线 |
| 手动填数据坚持不下来 | 数据模块变空壳 | 列数控制在必要范围；支持粘 CSV 降低录入成本 |
| 模板设计太复杂 | 用户懒得配，清单空着 | 空态引导 + 建模板即生成当天条目 |
| 删除店铺丢数据 | 历史条目变孤儿 | 只停用不删除 |
| 容器权限问题 | SQLite 写失败 | 部署步骤强制 `chown` |
| 备份未验证 | 出事时无法恢复 | 验收要求实际恢复一次 |
